Story Vault · simplification review · 26 July 2026

Keep the behavior. Delete the observability corridor.

The deterministic context selector is worth keeping. The full runtime trace is not: it creates paired APIs, crosses six layers, duplicates existing inspection views, and grows with chat size multiplied by retained requests.

− Recommended: remove retained per-request traces entirely, return plain message arrays again, then shrink the four-section ContextDocument into two small composition helpers.

Primary source of accidental complexity

One debug feature became a cross-system protocol

Each hop is individually reasonable. Together they turn optional diagnostics into a required concern of the hot path.

01 Projection Builds a metadata object for every item, including excluded history.
02 Context service Returns { messages, trace } and keeps parallel message-only wrappers.
03 Generation Threads traces through response, reasoning, and regeneration branches.
04 OpenRouter API Adds optional trace parameters across streamed and non-streamed request paths.
05 Request tracker Retains the per-item metadata beside the exact messages already sent.
06 Inspection UI Summarizes and renders the extra metadata through another helper and tests.
Request Inspection already stores the exact model input

TrackedRequest.inputMessages answers the most important debugging question: “What was actually sent?”

Chat Message Inspection already shows current LLM context

It displays inclusion and position for the selected message. A second retained trace overlaps this capability instead of replacing it.

Lean target

Four steps, plain arrays, one policy boundary

Keep each transformation explicit. Remove metadata that does not affect the request.

Chat events Persisted facts and lifecycle events remain unchanged.
GetMessages(policy) Apply compression, safe buffering, expiration, and Plan selection once. Return messages only.
Compose durable context Split history once; insert Memories and Character Sheets before the recent tail.
Build request messages Append the workflow prompt and send. Request tracking already captures the exact result.

Keep: behavior-reducing code

  • Immutable LLMContextProjectionPolicy.
  • Safe latest-chapter buffer and unique-ID invariants.
  • Linear note/reasoning retention scans.
  • ID-indexed message lookup.
  • Parallel, once-per-request source loading.
  • One book request assembler and precise response-prompt vocabulary.

Delete: observation-only plumbing

  • GetContext() and projection trace types/helpers.
  • All three build*WithTrace() methods and wrapper pairs.
  • contextTrace parameters in generation and OpenRouter.
  • TrackedContextTrace and retained trace data.
  • Context-assembly accordion, summarizer, and trace-only tests.
  • Section tracing inside ContextDocument.

Deletion-first sequence

Simplify in four reversible passes

Each pass should leave the build and exact message-array behavior green before the next begins.

01

Lock behavior, not implementation

Keep the exact cross-source ordering fixture and workflow output assertions as the contract.

  • Response and reasoning arrays
  • Regeneration truncation
  • Chapter/book specialized inputs
02

Remove the runtime trace corridor

Work from the UI backward until projection selection returns only LLMMessage[].

  • Delete UI and tracker shape
  • Delete API propagation
  • Collapse paired builders
  • Delete projection trace creation
03

Shrink the composition abstraction

Replace the four-array document plus render cycle with a history split and durable insertion helper.

  • splitRecentHistory()
  • insertDurableContext()
  • One consolidated-reasoning formatter
04

Compress test code without losing cases

Use behavior tables for retention, guidance, and feedback; retain one end-to-end parity fixture.

  • Delete trace-only suites
  • Parameterize repeated variants
  • Keep stress and correctness suites

False simplifications

Do not trade line count for a worse design

These moves make individual files look smaller while preserving or increasing system complexity.

No giant buildRequest(kind) switch Response, reasoning, regeneration, chapter, and book requests have meaningfully different contracts.
No service-per-workflow explosion Moving seven builders into seven classes adds dependencies and mocks without deleting decisions.
No weakened regression suite Delete tests only when their feature disappears or equivalent behavior is expressed more compactly.

Done means simpler
