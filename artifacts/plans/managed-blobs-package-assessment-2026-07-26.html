Three viable homes

Keep it in src

Fine if reuse never arrives.

  • No tooling change
  • Weak boundary enforcement
  • Does not test package consumption

npm workspace package

The useful middle ground.

  • Real package exports and build
  • Atomic app + package changes
  • No publishing or upgrade choreography

Publish to npm now

Creates obligations before demand.

  • Semver and changelog ownership
  • Release security and CI
  • Cross-version support and migration docs

Recommended sequence

Harden the contract

Inject storage, serialization, error reporting, retry policy, and timers. Normalize “not found” in the app adapter. Define concurrency, flush, delete, and disposal behavior.

Done when behavior is adapter-independent.

Incubate as a workspace

Move core code and tests to packages/managed-blob. Export only the class, client factories, and public types. Keep BlobAPI and all domain data types in the app.

Done when app CI consumes built package output.

Publish only after a gate

Publish a scoped 0.x package when a second real consumer exists, independent releases are useful, and the API has survived normal app development without repeated breaking changes.

Done when external versioning buys real autonomy.

Resolve before freezing a public API

Consistency

A pending fetch can race a save; refetches are not deduplicated; delete can trigger a subscriber refetch before deletion completes.

Lifecycle

Keyed instances remain cached indefinitely, and there is no public dispose/evict operation for timers and subscribers.

Status

Loading completion is not itself published to subscribers, and optimistic local data has no dirty or failed-save state.

Policy

“Not found” uses message matching, while every save failure is retried—even errors an adapter may know are permanent.

The publication gate

Second consumer

There is demonstrated reuse outside Story Vault UI.

Stable semantics

Concurrency and lifecycle behavior no longer churn.

Independent cadence

Package releases provide value beyond app releases.
