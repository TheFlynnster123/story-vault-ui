Context strategy · proposed

Compress the model’s view, not the user’s history.

Preserve every original message in the event stream and visible transcript. Attach an editable 2–3 sentence compression to eligible older text messages, then let the LLM projection substitute that representation at request time.

✓ Recommended. The current event-store → dual-projection → context-document architecture already has the right seam; this should be an additive overlay, never a destructive rewrite.

One source, two representations

The original remains canonical

Keep the same message ID, role, order, and edit history in both lanes. Only the content materialized for an LLM request changes.

User lane

Event store

Original MessageCreated / MessageEdited events remain untouched.

UserChatProjection

Projects the full original content plus optional compression metadata.

Visible transcript

Message bubble stays complete. Click → “View compression” → edit and save.
LLM lane

Compression event

Stores messageId, compressed content, and a source fingerprint.

LLMChatProjection

Chooses original or compressed content under the active age policy.

ContextDocument

Receives the substitute with the original ID, role, position, and traceability.
“Keep just these sentences in chat” should mean the LLM-bound chat payload. The UI transcript and persisted original must retain the full message.

Eligibility policy

Compress only ordinary text messages

Count newer qualifying messages after each candidate. When that count reaches configurable N, queue compression after the current response is safely saved.

Eligible

type === "message"

User, assistant, and ordinary system-role text created through MessageCreated. Apply a minimum source-length check so short messages are never made larger by “compression.”

Excluded

Structured and ephemeral items

Reasoning, image workflows, story, chapter, book, plan, note, and agent clarification items neither qualify nor advance the age counter.

Trigger

Post-response background task

Run after the assistant message persists, deduplicate by message ID, and never block the next visible response. Failure leaves the original context intact.

Prompt contract

Faithful, self-contained, brief

Preserve names, decisions, state changes, constraints, and essential dialogue intent. Add no facts. Return only 2–3 sentences with no preamble.

No recursion

Always summarize the original

Never summarize a prior summary. Manual compression edits update the overlay, not the source from which future regeneration is produced.

Suggested pilot

Tune N from traces

Start behind a setting with a conservative recent-message window and a meaningful minimum character count. Treat the exact defaults as a pilot choice, not a hard-coded product truth.

Lifecycle and races

A small event contract keeps replay deterministic

The source fingerprint is the guardrail: an async result generated from stale original content must never become active after an edit.

1

Message ages past N

The selector finds an eligible, visible text message with no current compression.

2

Generate from a snapshot

The service records a fingerprint, calls the configured low-cost model, and rejects no-savings output.

3

Persist compression

MessageCompressionCreated stores the message ID, 2–3 sentences, and source fingerprint.

4

Project or invalidate

A matching source activates it. MessageEdited invalidates it; a stale late response is ignored.

Chapter / book first If the message is hidden by structural compression, it remains excluded.
Message representation second A visible or chapter-buffered message uses its active compression when old enough.
Regeneration stays original GetMessage(id) returns source content; only GetContext() materializes the substitute.

Implementation path

Five bounded changes

Keep automatic activation behind settings until projection, race, and narrative quality tests pass. Each phase has a useful completion boundary.

1

Events + projection state

Add created/edited compression events, utilities, ChatService operations, replay handlers, and source invalidation.

Done: originals survive; both projections expose compression metadata.
2

Context substitution

Materialize compressed content in GetContext(), preserve ID/role/order, and extend trace entries with representation data.

Done: requests shrink without changing the visible transcript.
3

View + edit UX

Add “View compression” to the message overlay, an original-versus-compressed editor, a status cue, and inspector coverage.

Done: users can audit and correct every active substitute.
4

Generator + scheduler

Add prompt/model settings, an eligibility selector, post-response background orchestration, in-flight dedupe, and request tracking.

Done: newly eligible messages compress automatically without blocking chat.
5

Pilot + tune

Compare full and compressed requests on representative stories; inspect savings, continuity, failures, and manual correction rate.

Done: enable by default only after quality and savings justify it.

Verification

Test the semantic seams, not just the happy path

Existing projection and context-pipeline tests are the natural homes for most coverage; add focused UI and generation-service tests around them.

Area Required proof Failure prevented
Replay Created and edited compression events replay to the same current overlay; legacy chats remain unchanged. Non-deterministic state or migration breakage.
Eligibility Only ordinary text counts; reasoning, images, notes, plans, story, chapters, books, and clarifications are excluded. Unexpected cost and compression of structured context.
Concurrency An original edit during generation makes the late result inactive; duplicate schedulers produce at most one active result. Stale summaries and repeated billing.
LLM projection Same ID, role, order, and trace; only eligible old message content changes. Recent messages remain original. Broken regeneration, chronology, or role semantics.
Structural compression Chapter/book exclusion wins; a trailing chapter buffer may use message compression without revealing other hidden items. Double inclusion or loss of chapter behavior.
User experience Full bubble remains visible; compression is inspectable, editable, and clearly labeled as the model-facing representation. User confusion about what was deleted or changed.
Quality + cost Compression adds no unsupported facts, preserves continuity-critical details, and delivers material character/token savings. Paying for summaries that harm context or do not shrink it.

One product decision before implementation

Decide whether the first pilot is opt-in per chat or globally enabled with an escape hatch. The safer rollout is opt-in or disabled-by-default while the request inspector exposes original size, compressed size, active representation, and manual-edit rate.
