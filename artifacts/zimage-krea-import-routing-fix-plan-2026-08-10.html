Implementation plan · image model import

Route model families explicitly—never manufacture an empty AIR

Replace the current AIR-only assumption with a family resolver that produces valid SD, Anima, and Z-Image recipes, while clearly rejecting Krea/Comfy images that the hosted workflow cannot faithfully replay.

✓
Desired outcome: importing an image either creates a valid, submit-ready model configuration or explains exactly why replay is unsupported. Blank model fields and silent SDXL fallback disappear.

The behavior change

Image 135352590 is the forcing case: its only resource is a Krea 2 LoRA, even though the model title also mentions Z-Image.

Today

  • No checkpoint → look up baseModel in a four-entry map.
  • Krea 2 misses the map → return "".
  • Unknown ecosystem → silently classify as sdxl.
  • UI displays a blank Model (AIR) and allows saving it.

New import flow

One resolver owns classification. Mappers and UI consume its explicit result rather than guessing independently.

Read raw metadata

Keep resources, baseModel, AIR ecosystems, and the optional params.Model filename hint.

Resolve family

Normalize aliases such as zimageturbo, ZImageTurbo, and Krea 2.

checkpoint AIRbase modelfilenameLoRA AIR

Check replay support

Separate “recognized family” from “can be reproduced by our current orchestration input.”

Build typed input

Create a family-specific payload. Do not emit model: "" or incompatible fields.

Render honest UI

Show an AIR field only for AIR-backed families, a variant selector for Z-Image, or an actionable import error.

Routing decisions

The same import service can support multiple contracts without pretending they all use checkpoint AIRs.

SD1 / SDXL

Checkpoint AIR remains the model identifier. Existing behavior is preserved.

engine: "sdcpp"
model: urn:air:…

Anima

Use the built-in Anima ecosystem; retain an optional diffuser override only when truly present.

ecosystem: "anima"
diffuserModel?: urn:air:…

Z-Image

Map AIR/base-family evidence to the built-in variant token. Preserve compatible LoRAs.

ecosystem: "zImage"
model: "turbo" | "base"

Krea 2 / custom Comfy

Recognize it, but do not claim fidelity: current hosted Krea rejects LoRAs and uses a different FAL schema.

Return unsupported-replay with detected family and reason.

Implementation sequence

The order keeps each change testable and prevents the UI from getting ahead of the submission contract.

  1. Introduce a family resolution result

    Add a small, pure resolver returning SD, Anima, Z-Image variant, or unsupported replay. Give evidence precedence one searchable home.

    modelGeneration/ModelFamilyResolver.ts

  2. Represent family-specific inputs

    Turn ImageGenInput into a discriminated contract keyed by engine and ecosystem. Include zImage; do not make Krea fields masquerade as SD fields.

    api/ImageGenInput.ts
    ImageModelVariant.ts

  3. Replace AIR-only mapping

    Map the resolver result directly. Remove the empty-string fallback and make incompatible or missing evidence an explicit import failure.

    ImageModelMapper.ts
    BaseModelMapper.ts

  4. Normalize Z-Image at submission

    Guarantee the exact Civitai shape: sdcpp + zImage + turbo/base. Retain Anima normalization and SD behavior.

    CivitOrchestrationAPI.ts

  5. Make the editor family-aware

    Rename “Model (AIR)” only where it is an AIR. Show a Base/Turbo selector for Z-Image. Surface the unsupported Krea explanation in both import entry points.

    ParametersComponent.tsx
    ModelFromImage.tsx
    AddImageModelModal.tsx

  6. Lock the behavior with fixtures

    Use captured payload shapes rather than live API calls. Assert both import result and final submitted JSON.

    ImageModelMapper.test.ts
    CivitOrchestrationAPI.test.ts
    ModelFromImage.test.tsx

Guardrails and completion criteria

Keep this out of scope

  • Do not execute arbitrary embedded Comfy workflows from image metadata.
  • Do not “fix” Krea by dropping its LoRA without telling the user.
  • Do not add a fake Krea or Z-Image checkpoint AIR to BaseModelMapper.

Done when

  • No supported import can produce model: "".
  • Z-Image generates the documented orchestration payload.
  • Krea/Comfy limitations are visible before save or generation.
  • SD1, SDXL, Pony, Illustrious, and Anima tests remain green.
